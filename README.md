# Teleperformance Workforce Analysis

An HR attrition dashboard built in Power BI. It uses a star-schema model, DAX measures, and custom HTML/CSS visuals to show where attrition happens, why it happens, and which employees need attention first.

> Case study for a BI Analyst role (GBS BI Hub). The dataset is a public-style HR attrition sample, not real employee data.

---

## Highlights

- **Star schema** built in Power Query: one employee-grain fact table and small dimensions (job, demographics, education, work conditions, and age, tenure, income and distance bands).
- **6 pages:** a landing page plus five analysis pages, each at a fixed 1280×720.
- **DAX-driven HTML visuals:** every chart, KPI card and table is generated by a DAX measure, so it reacts to slicers like any native visual.
- **Good / mid / bad colouring:** green, yellow and red status colours with thresholds you can edit.
- **Light and dark mode** switch, plus a slide-out **filter panel** (Department, Overtime).
- **Early-warning list:** a rule-based risk score that flags current employees showing several warning signs.

Overtime, early tenure and low pay stand out as the strongest signals. These numbers come from the sample dataset, so treat them as a demonstration of the method.

## Data model

```
Dim_Job ─────────────┐
Dim_Demographic ─────┤
Dim_Education ───────┤
Dim_WorkCondition ───┼──►  Fact_Employee  (1 row per employee)
Dim_AgeBand ─────────┤
Dim_TenureBand ──────┤
Dim_IncomeBand ──────┤
Dim_DistanceBand ────┘
(+ small score-label dimensions, and a disconnected Theme table)
```

- All relationships are one-to-many, single direction, from dimension to fact.
- Constant columns (`EmployeeCount`, `Over18`, `StandardHours`) and noise columns (`DailyRate`, `HourlyRate`, `MonthlyRate`) are removed.
- Dataset: 1,470 rows, 35 columns, no missing values.

## Getting started

### Requirements

- Power BI Desktop (recent version, with DAX query view)
- The **HTML Content** custom visual (from AppSource)

### Setup

1. **Load the data.** Open the Excel file in Power Query and build the staging query, band and label columns, the dimension tables with index keys, and `Fact_Employee`. Set every numeric column to Whole Number, because text types break the measures.
2. **Create relationships** in Model view: each dimension key to the matching fact column.
3. **Create the theme table** (Modeling → New table):
   ```dax
   Theme = DATATABLE ( "Mode", STRING, { { "Light" }, { "Dark" } } )
   ```
4. **Add the base measures** (Total Employees, Attrition Rate, and so on) to a measures table named `DAX`.
5. **Load the HTML measures.** Paste each `.dax` file into DAX query view and click **Update model with changes** (twice, so measures that depend on each other resolve).
6. **Build each page.** Set the canvas to Custom 1280×720, add one HTML Content visual at X 0, Y 0, size 1280×720, and drop the matching measure into Values.
   - In Format visual → General, set padding to 0 and turn off the title, background, border and visual header.
7. **Add the controls** (filter button, Department and Overtime slicers, Theme slicer, bookmarks). Use View → Sync slicers so selections carry across pages.

## Customisation

- **Colour thresholds:** change the `tGood` / `tBad` style values at the top of each page measure (default: attrition up to 12% is green, up to 18% is yellow, above that is red).
- **Risk score:** the five warning signs (overtime, job satisfaction of 2 or lower, work-life balance of 2 or lower, 5 or more years without promotion, frequent travel) can be adjusted in the `RiskScore` column.
- **Palette:** a purple-to-magenta gradient inspired by the Teleperformance brand. Colours are defined as variables inside each measure.

## Known limitations

- The HTML Content visual cannot be clicked to filter or navigate. Filtering and page navigation use native Power BI slicers, buttons and bookmarks placed over or beside the HTML.
- Hover effects and animations use a CSS `<style>` block. Layout and colour are inline, so pages still render if a `<style>` block is stripped.
- Segments with fewer than 30 employees give volatile rates and are flagged where relevant.
- Attrition rates are descriptive. This is a single snapshot, so the dashboard shows association, not causation.

## Privacy note

The early-warning list shows employee numbers only. If you adapt this to real HR data, restrict access to that list, and do not commit real employee data to a public repository.
